# UE5 GAS教程 第1课：Gameplay Ability System整体介绍

## 课程目标

本节课不编写代码，主要建立对 GAS（Gameplay Ability System）的整体认识。

学习完本节后，应该理解：

- GAS是什么
- GAS解决什么问题
- GAS的核心组成
- GAS和普通系统抽象有什么区别
- 为什么大型游戏会需要GAS


本节核心：

> GAS最大的价值，不是提供了一套技能API，而是把游戏中的能力、属性、状态和效果变化抽象成了一套统一系统。


---

# 一、什么是GAS？

GAS全称：

Gameplay Ability System

是 Unreal Engine 提供的一套游戏能力系统框架。


主要用于管理：

- 技能（Gameplay Ability）
- 属性（Attribute）
- 效果（Gameplay Effect）
- 状态（Gameplay Tag）
- 表现（Gameplay Cue）


常见应用：

## RPG

例如：

- 火球术
- 治疗术
- 护盾
- 中毒
- 装备属性


## MOBA

例如：

- 技能释放
- 技能冷却
- 蓝量消耗
- 控制效果
- Buff效果


## MMO

例如：

- 角色属性
- 装备系统
- 天赋系统
- 大量状态效果


这些游戏都有一个共同问题：

> 当游戏中的能力越来越复杂，如何保持系统结构清晰？


---

# 二、为什么需要GAS？

在理解GAS之前，需要先理解传统方式的问题。

---

# 传统技能系统

假设制作一个RPG角色：

```
Character

├── 普通攻击
├── 火球术
└── 治疗术
```


每个技能自己处理全部逻辑。


例如：

## 火球术

流程：

```
玩家按下技能

↓

检查法力

↓

消耗法力

↓

播放动画

↓

生成火球

↓

检测命中

↓

造成伤害

↓

添加燃烧

↓

进入冷却
```


传统代码：

```
Fireball()

{
    消耗蓝量();

    播放动画();

    创建火球();

    造成伤害();

    添加燃烧();

    开始冷却();
}
```


刚开始没有问题。


但是继续增加：

- 冰球术
- 雷电术
- 护盾
- 中毒
- 增伤
- 减伤
- 装备效果
- 天赋效果


每个技能都会包含：

```
技能逻辑

+
属性修改

+
状态变化

+
持续时间

+
冷却

+
表现
```


最后：

技能之间大量重复。


---

# 三、GAS的核心思想

传统思维：

```
我要实现一个技能

↓

写一个技能函数

↓

里面处理所有逻辑
```


GAS思维：

```
我要实现一个能力

↓

拆分成多个通用模块

↓

组合形成最终效果
```


例如：

一个火球术：

表面看：

```
火球术
```


但是内部：

```
火球术

=

释放能力

+

消耗法力

+

造成伤害

+

添加燃烧

+

技能冷却

+

视觉表现
```


这些部分可以独立存在，并且被其他系统复用。


---

# 四、GAS和其他抽象系统有什么区别？

很多人会疑惑：

> 这不就是普通程序设计里的抽象和组件化吗？为什么GAS值得单独学习？


答案：

GAS抽象的不是一个固定功能，而是：

> 游戏对象运行过程中不断变化的规则。


---

# 1. UI系统抽象的是展示结构

例如UMG：

```
Widget

├── Button
├── Panel
└── Text
```


解决：

- 如何显示
- 如何布局
- 如何响应输入


UI关注的是：

```
内容如何呈现
```


---

# 2. 背包系统抽象的是数据管理


例如：

```
Inventory

Item

Slot

Stack
```


解决：

- 物品存储
- 增删改查
- 排序管理


关注：

```
数据如何保存
```


---

# 3. AI系统抽象的是决策过程


例如：

```
感知

↓

判断

↓

选择行为

↓

执行
```


关注：

```
对象如何做决定
```


---

# 4. GAS抽象的是动态规则变化


游戏角色不是固定数据。

角色会不断变化：

初始：

```
攻击力100
移动速度500
可以释放技能
```


获得装备：

```
攻击力120
```


受到中毒：

```
每秒掉血
```


被沉默：

```
无法释放技能
```


进入狂暴：

```
攻击力提升50%
速度提升20%
```


这些状态同时存在。


所以GAS需要解决：

- 如何添加变化
- 如何移除变化
- 如何叠加变化
- 如何判断当前状态
- 如何组合多个规则


---

# 五、GAS核心框架


```
                 Ability System Component
                           |
        ------------------------------------------------
        |                  |             |             |
     Ability          GameplayEffect  Attribute   GameplayTag
      能力                 效果           属性          标签


                           |
                    Gameplay Cue
                       表现效果
```


---

# 六、GAS核心模块


# 1. Gameplay Ability

负责：

> 玩家能够主动执行什么。


例如：

- 火球
- 闪现
- 治疗
- 冲锋


负责：

- 技能触发
- 技能流程


不负责：

- 具体伤害
- 属性修改
- 状态变化


---

# 2. Gameplay Effect


负责：

> 游戏中的变化。


例如：

伤害：

```
Health -100
```


增加攻击：

```
Attack +20
```


中毒：

```
每秒减少10生命
持续5秒
```


减速：

```
移动速度-30%
持续3秒
```


技能、装备、Buff最终都可以变成Effect。


---

# 3. Attribute


负责：

> 角色拥有的数据。


例如：

```
Health

Mana

Attack

Defense

Speed
```


Effect修改Attribute。


例如：

```
火球命中

↓

Damage Effect

↓

Health减少100
```


---

# 4. Gameplay Tag


负责：

> 描述对象当前状态。


例如：

```
State.Stunned

State.Burning

State.Dead
```


技能释放前：

检查：

```
是否拥有State.Stunned

如果有

禁止释放技能
```


---

# 5. Gameplay Cue


负责：

> 游戏表现。


例如：

伤害逻辑：

```
Health -100
```


表现：

```
受击动画

伤害数字

粒子效果

声音
```


---

# 七、案例分析


# 案例1：火球术


## 不使用GAS


```
Fireball()

{

检查蓝量

消耗蓝量

播放动画

生成火球

造成伤害

添加燃烧

开始冷却

}
```


所有逻辑集中。


问题：

以后增加：

火焰剑：

```
火焰伤害增加30%
```


火焰天赋：

```
燃烧时间增加
```


火焰药水：

```
下一次火焰技能强化
```


都会和火球代码产生关系。


---

## 使用GAS


火球拆分：


Ability：

```
负责释放火球
```


Mana Cost Effect：

```
Mana -20
```


Damage Effect：

```
Health -100
```


Burn Effect：

```
持续伤害5秒
```


Cooldown Effect：

```
5秒内不能再次释放
```


Gameplay Cue：

```
火球模型

爆炸效果

声音
```


最终：

```
Fireball Ability

+

Mana Cost Effect

+

Damage Effect

+

Burn Effect

+

Cooldown Effect

+

Gameplay Cue
```


---

# 案例2：装备系统


## 不使用GAS


火焰剑：

```
攻击力+20

火焰伤害+10%

攻击附带燃烧
```


装备代码负责：

- 修改属性
- 添加效果
- 卸载恢复


随着装备增加，逻辑越来越复杂。


---

## 使用GAS


火焰剑：

```
添加Attack Effect

+

添加Fire Damage Effect

+

添加Burn Effect
```


装备只是效果集合。


卸下：

移除Effect。


---

# 案例3：狂暴Buff


## 不使用GAS


```
开启狂暴

↓

攻击增加

↓

速度增加

↓

播放特效

↓

10秒后恢复
```


如果：

技能提供狂暴

药水提供狂暴

装备提供狂暴


需要重复实现。


---

## 使用GAS


狂暴：

```
Berserk Effect


Attack +50%

Speed +20%

Duration 10秒


Tag:

State.Berserk
```


任何来源：

技能、装备、药水

都只是添加同一个Effect。


---

# 八、GAS的优势


## 1. 复用

一个Effect可以被：

- 技能
- 装备
- 药水
- 天赋

重复使用。


---

## 2. 解耦

技能不用关心：

- 属性如何修改
- 状态如何管理
- 表现如何播放


---

## 3. 扩展方便

新增内容：

更多时候是组合已有模块。


例如：

新增火焰装备：

```
攻击Effect

+

火焰伤害Effect

+

燃烧Effect
```


---

## 4. 统一管理复杂规则


大型游戏中：

```
100个技能

500件装备

大量Buff

大量状态

多人联机
```


如果没有统一系统，复杂度会快速增加。


---

# 九、总结


传统方式：

```
一个技能

↓

一套完整代码

↓

自己处理所有逻辑
```


GAS：

```
一个能力

↓

Ability

+

Gameplay Effect

+

Attribute

+

Gameplay Tag

+

Gameplay Cue

↓

组合成最终效果
```


GAS最大的改变：

> 从“实现一个技能”，转变为“组合多个系统，形成一个能力”。


GAS不是因为发明了组件化而特殊。

它特殊在：

> 它针对游戏中大量动态变化的能力、状态和效果，提供了一套统一的规则管理框架。
